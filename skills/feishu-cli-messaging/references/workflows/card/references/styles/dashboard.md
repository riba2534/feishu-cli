# 仪表盘类型卡片

## 使用边界

只有用户明确点选仪表盘、dashboard、看板风、监控态势型、经营汇报型、趋势分析型、排行洞察型、健康评分型、极简概览型时读取。不要因为 KPI、指标、趋势、排行、日报、周报、报表等内容词自动套用本主题。

## 推荐结构

摘要结论 -> 关键指标概览 -> 图表/表格 -> 风险、洞察或下一步 -> 来源驱动行动按钮 -> 来源/口径说明。首屏必须包含时间窗口、数据口径或“示例数据/模拟数据”。

所有仪表盘子模板同样适用全局行动按钮规则：只要数据源、原始报表、文档、表格/Base、日程、任务、安装指南、表单或详情页有真实 URL，就在来源说明前生成行动按钮。单个目标用通栏按钮；2-3 个同等重要目标用一个通栏 `column_set`，内部 `weighted` 等比分栏。底部全局行动区域的最外层按钮或按钮组必须用四值 `margin:"20px <右> 0px <左>"` 补 20px 上间距，并保留仪表盘卡片原本的左右页边距。按钮文案按来源类型配置，例如 `打开表格`、`打开 Base`、`查看详情`、`打开文档`、`查看日程`，不要统一写成泛化的“查看详情”。

所有指标分栏、排行分栏、风险分栏和图表外壳都必须和页面背景形成可见色阶梯度。分栏背景不能复用页面底色、普通 panel 或图表画布；如果预览中列块和背景融在一起，必须改浅/改深一档或增加同色系边界，不要只靠文字颜色区分。

## 子风格

| `style_id` | 子风格 | 重点 | 起稿结构 |
|---|---|---|---|
| `dashboard-monitoring` | 监控态势型 | 状态、时间窗口、核心异常；头部可用 `blue/orange/red` | 结论 → 指标 → 异常与处置 surface |
| `dashboard-business` | 经营汇报型 | 一句业务结论、KPI 达成、主要变化；头部可用 `indigo/blue` | 结论 → KPI → 分隔线 → 主要变化与下一步 |
| `dashboard-trend` | 趋势分析型 | 趋势方向、拐点、原因；优先 `chart` | 结论 → 拐点与原因 → 趋势指标 |
| `dashboard-ranking` | 排行洞察型 | 榜首/末尾、最大变化、异常项；优先 `table` 或柱图 | 结论 → 排名表 → 异常项 |
| `dashboard-health` | 健康评分型 | 评分/等级、扣分主因；状态色跟随评分 | 结论 → 评分指标 → 分隔线 → 扣分 surface |
| `dashboard-minimal` | 极简概览型 | 一句结论、3–4 个核心指标、1 个风险或下一步 | 结论 → 指标 → 轻量风险/下一步 |

可以从 card workflow 目录直接生成起稿：

```bash
python3 scripts/style_assets.py starter dashboard-monitoring \
  --title "支付链路监控" \
  --summary "过去 30 分钟错误率回落" \
  --meta "2026-07-29 16:00–16:30 · UTC+8 · 全量请求" \
  --metric "成功率=99.97%" \
  --metric "P95=182 ms" \
  --output /tmp/dashboard-card.json
```

## 图表规则

趋势、对比、占比、排行优先使用 Card JSON 2.0 `chart` 或 `table`，不要用 Markdown/ASCII
伪图。复杂卡片生成后运行 `python3 scripts/lint_card.py --strict <card.json>`。

- 图表主题尽量避免深黑色，尤其不要使用纯黑或接近纯黑作为图表大面积背景；飞书 dark mode 下容易和页面背景混淆。
- 监控态势、经营看板、酷炫暗色风可以用深灰蓝、靛蓝、紫蓝、墨绿、暖灰等“有色暗底”，并保留轴线、网格线、图例、数据色和容器背景之间的明度差。
- 如果截图中图表区域和页面背景连成一片，必须改浅一档背景或增加边界/浅色 surface，不要继续加深。
